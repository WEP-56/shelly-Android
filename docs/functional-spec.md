# Shelly Android 功能描述

状态：草案，等待 HTML 原型和产品反馈确认

本文只约定产品功能、信息结构和关键交互。颜色、字号、圆角、具体动效
曲线和组件尺寸以 HTML 原型为准；实现必须遵守 Android 使用习惯和
`AGENTS.md` 中的工程约束。

当前视觉原型位于 `md3-ssh-client-mockup/`，其中附带的页面截图可直接作为
实现参照。已知差异：原型终端截图尚未包含 Termux 式扩展快捷键栏，正式
Flutter 实现必须补齐，不能按截图省略。

## 1. 产品定位

这是一个 Android 优先的 SSH 工作台。用户打开应用后，目标是快速找到
设备、进入终端、执行命令，并在不离开当前 SSH 上下文的情况下完成文件、
命令集、历史和 Agent 操作。

第一版不追求 ServerBox 的服务器监控广度，也不提供本地终端。重点是：

- 可靠的 SSH 连接和主机指纹确认
- 适合触屏的远程终端
- SFTP 文件浏览和传输
- 可复用的命令便签与历史命令
- 受用户控制的只读 Agent

## 2. 视觉与交互原则

### 2.1 视觉

- 使用 Material 3 组件和状态模型。
- 主色调参考 x.com 的黑白关系，但浅色模式避免大面积纯白直射感；使用
  Material 3 的 surface、surface container 和低对比层级区分区域。
- 深色模式以接近黑色的表面为主，避免所有区域都是同一块黑色。
- 页面文字只承担必要的信息确认，功能入口优先使用图标；图标需要提供
  无障碍语义和必要的长按提示。
- 动效用于导航、面板展开、连接状态和内容切换，节奏连续但不抢终端焦点。

### 2.2 移动端交互

- 点击执行主要动作，长按显示上下文操作，滑动用于关闭侧栏或返回上一级。
- Android 返回键按层级处理：先关闭键盘、菜单或辅助面板，再考虑离开当前
  终端；不要直接丢失用户正在输入的内容。
- 终端必须提供触屏可用的 Ctrl、Alt、Esc、Tab、方向键、复制、粘贴和
  中断操作。
- 主要操作不能依赖悬停、右键或桌面端多栏布局。

## 3. 应用结构

根页面由上下两个区域组成：上方是当前页面内容，下方是固定 Dock。

Dock 只有两个入口，不显示文字标签：

- 云图标：Server 页面
- 齿轮图标：Settings 页面

当前页面的选中状态必须能仅通过图标颜色、容器形状或指示器识别；仍需为
屏幕阅读器提供“服务器”和“设置”的语义标签。

### 3.1 Server 页面

定位：设备入口和连接管理，不承担监控大盘。

页面内容：

- 已保存设备列表
- 设备的名称、地址、端口、用户名和连接状态摘要
- 添加设备入口
- 空列表状态

添加设备流程：

1. 点击添加图标，打开设备编辑页。
2. 填写名称、主机、端口、用户名和认证方式。
3. 选择密码、私钥或 keyboard-interactive 等认证资料。
4. 保存后回到设备列表，不自动连接，除非用户明确选择“保存并连接”。

设备列表行为：

- 点击设备卡片进入 SSH 连接流程。
- 长按打开编辑、复制、置顶、删除等管理操作。
- 删除设备只删除本地配置，不影响远程主机；需要确认。
- 连接中的设备显示轻量状态，不在列表中展示大段日志。

### 3.2 Settings 页面

定位：应用级和终端级偏好设置。首版只放常用且可解释的选项：

- 外观：跟随系统、浅色、深色
- 终端：字号、字体、光标、滚动缓冲、铃声、复制行为、扩展快捷键布局
- 安全：已知主机、指纹记录、敏感信息锁定、生物识别锁
- 文件：默认下载目录、覆盖策略、并发传输数
- Agent：provider、模型、流式传输、工具策略、工作规范和历史记录
- Web Search：搜索 provider、API Key 和启用范围
- 关于：版本和开源许可

Agent 设置至少支持：

- 添加、编辑、删除和选择默认 provider；provider 类型至少包括
  Messages 和 Responses。
- 配置 endpoint、model、API Key、超时、最大 loop 次数和是否允许流式输出。
- 编辑、导入、导出 Agent 工作规范 `AGENTS.md`。它可以是全局规范，也可以
  覆盖到单个设备，但不能覆盖产品的只读和用户审批安全边界。这里的文件是
  产品数据中的 Agent 指令，不是仓库根目录给编码 LLM 使用的 `AGENTS.md`。
- 配置 Web Search provider 和 API Key。搜索只能由 Agent 的 read 工具调用，
  Key 不进入提示词、终端、历史或普通日志。
- 配置生物识别锁定范围：应用启动、打开 Agent、查看 provider Key、查看私钥。

设置项应按功能分组，不要把 ServerBox 的全部平台选项搬进来。

## 4. SSH 连接流程

用户从 Server 页面点击设备后，进入连接态页面。连接态按以下顺序处理：

1. 创建连接并显示短暂的连接状态。
2. 首次遇到未知主机指纹时，显示主机、端口、密钥类型和指纹。
3. 用户确认信任后写入已知主机；拒绝则终止连接。
4. 进入认证流程。密码、私钥口令或 keyboard-interactive 提示不能写入
   普通日志。
5. 认证成功后创建终端会话，按终端尺寸申请远程 PTY。
6. 连接失败时保留返回入口和重试操作，并给出可理解的失败原因。

连接状态至少包括：连接中、等待指纹、等待认证、已连接、重连中、已断开。
“已连接”不能仅由页面是否打开推断，必须由真实 SSH 会话状态决定。

## 5. SSH 终端页面

终端页面是应用的核心工作区，默认保持干净、沉浸和高对比可读，不在画面
上堆叠功能按钮。

顶部工具栏从左到右：

- 返回图标：退出当前连接
- 文件夹图标：打开文件侧栏
- 右侧三横线图标：展开辅助功能列表

三横线展开后，在工具栏下方显示窄列表。列表只显示图标和极短标签，点击
一个功能后收起列表并打开对应工作区。

### 5.1 终端基础行为

- 远程输出持续流入终端，不因打开侧栏而销毁会话。
- 输入法、中文、Emoji、全屏程序、颜色、滚动和选区遵循终端模拟器能力。
- 打开键盘时不能遮挡当前输入行；终端可滚动到输入位置。
- 终端失焦后重新获得焦点时，不应自动发送额外字符。
- 长按终端内容提供复制、全选、粘贴和搜索等上下文操作。

### 5.2 Termux 式扩展快捷键

正式终端需要在软键盘上方提供紧凑的扩展快捷键栏。它是移动端核心输入能力，
即使 HTML 原型未画出也必须实现。

默认键位至少包含：

- `Esc`、`Ctrl`、`Alt`、`Tab`
- 上、下、左、右方向键
- `Home`、`End`、`PgUp`、`PgDn`
- 常用 shell 字符 `-`、`/`、`|`、`~`

交互要求：

- 竖屏空间不足时允许横向滚动或切换第二组键，不压缩终端到不可用高度。
- `Ctrl` 和 `Alt` 点击后进入单次组合状态，发送下一个按键后自动释放；长按或
  双击可以锁定，再次点击解除。锁定状态必须有明显但克制的视觉反馈。
- `Shift+Tab` 等次级组合可以通过长按键位或修饰键组合发送，不为每个组合单独
  堆按钮。
- 方向键和翻页键支持长按连续发送，并提供轻量触觉反馈。
- 快捷键必须进入终端的按键编码通道，不能当作普通文本拼接，确保 Vim、tmux、
  less、top 等程序收到正确控制序列。
- 快捷键栏只在终端可输入时出现；打开 Agent 输入框时需要明确当前焦点，不能把
  Agent 文本误发到远程终端。
- 用户可以在 Settings 中调整顺序、隐藏不常用键或恢复默认布局。

### 5.3 返回和断开

- 有输入法时，第一次返回只收起输入法。
- 有打开的辅助面板时，返回只关闭面板。
- 没有未提交输入且会话空闲时，返回直接断开并回到设备列表。
- 有正在执行的命令、未提交输入或传输任务时，返回需要确认，避免误断开。
- 断开后释放 SSH、Shell、SFTP、订阅和定时器；页面不能继续显示“已连接”。

## 6. 辅助功能

同一时间只打开一个辅助工作区。打开新的功能时，旧的 Agent、侧栏或菜单
先关闭，再切换到新功能。

### 6.1 Agent

定位：当前 SSH 上下文中的专业只读 Agent。它可以理解终端、读取远程信息、
查阅外部文档并提出操作方案，但不能自行改变远程状态。

Agent 或其中的 LLM 只能通过工具读取上下文，不能拿到原始 SSH socket、密码、
私钥、provider Key 或未授权的应用数据库。它的“自身定位”由产品安全提示词、
用户的 `AGENTS.md` 工作规范和当前设备上下文共同构成；用户规范不能覆盖产品
安全规则。

#### 工具边界

Read 类工具可以强大，但必须是无副作用的读取：

- 读取当前终端可见内容、有限滚动缓冲、当前输入、工作目录、终端尺寸和连接状态。
- 读取最近命令、退出状态、耗时和受长度限制的输出摘要。
- 通过 SFTP 读取远程目录、文件属性、文本内容和可预览文件；不得写入、删除或改名。
- 读取按需获取的服务器状态快照；状态采集本身不能隐式执行远程命令。
- 调用 Web Search 获取外部资料；搜索 Key 由应用托管，不能被模型读取。

任何需要向远程终端发送字符的操作都属于 Write 类，即使命令本身看起来是
只读的（例如 `df -h`）。Write 类工具只有一个弱能力：申请发送一个或多个完整
命令，不能直接执行，不能拆成隐藏的后续命令，也不能代替用户确认。

#### Provider 与运行时

- Provider 适配器至少支持 Messages 和 Responses 两种协议形态。
- 统一转换为内部事件：文本增量、provider 允许展示的状态摘要、工具调用增量、
  工具结果、用量、完成、取消和错误。不得把模型私有思维链直接展示给用户。
- 支持流式响应。Agent 对话区要实时显示文本增量和工具状态，不能等整轮完成
  后才一次性渲染。
- 支持 tool loop：模型发起 read 工具后继续生成；申请命令并得到用户批准、
  执行完成后，再把结果作为下一轮工具结果交给模型。
- 每轮和整次任务都有最大步数、超时、取消和上下文长度限制，避免工具死循环。
- Provider 的系统/开发者消息必须明确 Agent 的能力边界、当前设备、输出格式和
  审批规则；`AGENTS.md` 作为用户可编辑的工作规范注入，但优先级低于安全规则。

#### 交互流程

1. 点击 Agent，终端区域缩小到上半部分，下半部分出现对话区域。
2. 用户输入问题；应用构建最小必要上下文，不上传密码、私钥和无关历史。
3. Provider 开始流式返回。文本、read 工具调用和状态实时显示。
4. 如果模型申请一个或多个命令，界面显示完整命令、目标设备、申请原因和预期
   读取结果；用户可以全部批准、逐条批准、编辑后批准或拒绝。
5. 只有用户批准的原始命令才会写入终端。执行输出进入普通终端，同时作为受限
   工具结果回传给 Agent；模型不能声称执行了未批准的命令。
6. Agent 可以继续 loop，读取新的输出并给出下一步建议，直到完成、用户停止、
   达到上限或发生错误。
7. 用户可以随时停止流式响应或关闭分割区域；停止只取消 Agent 任务，不销毁
   SSH 终端连接。

对话区需要区分文本增量、读取工具、待审批命令、执行中、执行结果、拒绝、取消
和错误状态。任何写入远程主机的动作都必须有可见的用户操作记录。

### 6.2 状态

定位：按需查看当前服务器状态，不做持续监控面板。

- 点击后打开 Material 3 对话框或底部弹层。
- 显示主机名、系统、CPU、内存、磁盘、负载、运行时间等轻量摘要。
- 数据通过当前 SSH 连接按需获取；加载时显示明确状态，失败时可重试。
- 关闭弹层不影响终端会话。
- 首版不引入后台 Agent、历史图表或持续轮询。

### 6.3 便签

定位：用户维护的可复用命令集，不是自由文本笔记。

数据至少包含：名称、命令、描述、标签或分组、创建/更新时间、可选的目标
设备范围。

流程：

1. 点击便签，在终端右侧打开侧栏。
2. 侧栏显示搜索、分组和命令条目。
3. 点击条目打开操作菜单：插入、运行、编辑。
4. 插入只填入终端输入区，由用户继续修改或发送。
5. 运行显示确认并直接发送；需要处理交互式命令时，回到终端完成输入。
6. 长按条目可编辑、复制、置顶或删除；删除需要确认。

便签内容默认全局可用，但允许按设备过滤；命令本身不保存密码或私钥。

### 6.4 历史

定位：当前用户实际执行过的命令记录，默认由终端自动采集。

记录至少包含：命令文本、目标设备、时间、退出状态、耗时；输出只保存可控
长度的摘要，避免本地数据库无限增长。

流程：

1. 点击历史，在终端右侧打开侧栏。
2. 默认按最近执行时间倒序，可按设备、成功/失败和关键词筛选。
3. 点击记录可插入；运行前仍需用户确认。
4. 长按记录可置顶、编辑为便签、删除或清空历史。
5. 历史不允许无提示地改写原始命令；编辑应创建便签或新的命令记录。

便签是“主动维护的命令资产”，历史是“被动产生的执行记录”，两者在界面
上应保持不同的图标和操作语义。

## 7. 文件侧栏

文件夹图标打开终端右侧文件侧栏，不离开当前 SSH 页面。

侧栏内容：

- 当前远程路径和返回上级入口
- 当前目录的文件/文件夹列表
- 当前目录项目数；如果是分页或延迟加载，显示“已加载数量”，不要伪装成总数
- 搜索、刷新、排序和选择模式
- 上传、下载、创建目录、重命名、删除等操作

文件流程：

1. 打开侧栏后通过 SFTP 加载当前路径。
2. 点击文件夹进入目录；点击文件显示预览或操作菜单。
3. 上传通过 Android 文件选择器选择本地文件，显示队列和进度。
4. 下载默认写入设置中的目录，完成后提供打开或分享入口。
5. 同名文件出现覆盖、跳过、重命名选择；删除和递归操作需要确认。
6. 传输失败、暂停、取消和重试状态必须可见，不得静默丢失任务。

终端连接和文件侧栏共享同一个 SSH 客户端，但 SFTP 句柄独立管理；关闭
侧栏只释放文件浏览资源，不应断开终端。

## 8. 数据边界

按设备保存：连接参数、认证方式引用、已知主机关系、终端恢复信息、历史筛选。

全局保存：便签、主题、终端偏好、文件传输偏好、Agent 设置、默认 provider 和
全局 `AGENTS.md` 工作规范。

按设备可覆盖：Agent 工作规范、允许读取的上下文范围、历史筛选和默认远程路径。

安全存储：密码、私钥、私钥口令、Agent provider Key、Web Search API Key。
普通数据库不得保存这些秘密的明文，也不得把它们写入日志、历史或 Agent 上下文。

## 9. 首版验收重点

- 新建设备、编辑设备、删除设备和首次指纹确认完整可用。
- 密码和私钥两种常用认证能够进入终端。
- 终端支持中文输入、复制粘贴、Ctrl/Alt/Esc/Tab 和全屏命令。
- 终端提供 Termux 式扩展快捷键栏，修饰键、方向键、翻页键和控制序列在
  Vim、tmux、less 等程序中行为正确。
- Agent 支持 Messages/Responses provider、流式输出、read 工具、命令申请和
  用户批准后的 tool loop，且不会直接执行 write 工具。
- Agent、状态、便签、历史和文件侧栏可以在不销毁终端的情况下切换。
- SFTP 浏览、上传、下载、重命名、删除和失败重试有明确反馈。
- Android 返回键、软键盘、旋转和断线状态没有误操作或假连接。
- 深色/浅色模式下信息层级清晰，纯白区域不过度刺眼。
- Provider Key、Web Search API Key 和私钥可以由生物识别锁保护。

## 10. 待确认问题

以下问题不影响 HTML 原型继续制作，但在正式实现前需要定稿：

1. Server 页面是否需要“最近连接”或“置顶设备”分组，还是单一列表？
